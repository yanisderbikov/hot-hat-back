# SCRUM-59 — Обратимый пробный режим Wan 3.0 720p

Дата: 21.11.2026. Это **интеграция без платного end-to-end испытания**, пока нет нового явно подтверждённого заказа владельца.

## Что переключено

- **Только новые** задания `/neuro-replacement/` (простой 20–30-секундный загруженный видеообразец) и новые задания игрового теста с динамическим сценарием выбирают `wan-3`, разрешение `720p`.
- `GENAPI_API_KEY` остаётся прежним. Отдельный WAN API-ключ не нужен.
- Старые job с GenAPI task ID `kling-video-o3` продолжают использовать Kling при GET/истории/recovery и не переписываются.
- Сохраняем модель на уровне каждой новой job: `provider_requests["__diag.videoModel"]`. В owner status открыто поле `videoModel`.
- Для Wan отправляем HTTPS **только `video_urls`** (8-секундный identity reference), `duration`, `resolution="720p"`, `aspect_ratio="16:9"`, `audio=false`, `enable_prompt_expansion=false` и сцену. **Не отправляем одновременно `image_url`, `end_image_url`, `image_urls` или `audio_urls`**: GenAPI возвращает HTTP 422 на несовместимое сочетание `image_url` + `video_urls`. JPEG первого кадра остаётся в приватном S3 и доступен владельцу для скачивания, но не передаётся вместе с `video_urls`. `elements`, `pro`, `generate_audio` от Kling не отправляются.
- Сохраняем внешнюю озвучку Gemini TTS → Chatterbox → Lip Sync и обработку Longpipe после получения итогового файла. Никаких гарантий качества жестов и сходства без реального MP4.
- Проверяем URL/media и дикцию до дорогого видео. Отправляем **не больше одного платного POST на этап**, сохраняем ID перед проверкой результата, существующий оплаченный ID повторно не создаётся.
- Предварительная цена (без гарантии максимума) выводится до явного согласия: Wan 25 ₽/сек + оценка голосовых этапов.

## Откат

Для **новых** заданий установить `NEURO_NEW_VIDEO_MODEL=kling-video-o3` в переменных backend Railway. Для возврата к Wan — `NEURO_NEW_VIDEO_MODEL=wan-3`. Старые job всегда читаются по собственной сохранённой модели, независимо от флага. Неверное значение означает отказ без новой оплаты.

## Предварительная проверка и ограничения

- Wan reference payload использует публичную схему https://gen-api.ru/model/wan-3/api.
- Цена 720p — 25 ₽/сек https://gen-api.ru/model/wan-3.
- Настройка не выполняет GenAPI POST и не требует пополнения. Пользователь самостоятельно проверяет баланс на https://gen-api.ru/.
- Полноценный тест на новом оплачиваемом 10-секундном ролике нужно провести после пополнения и подтверждения в интерфейсе. Отдельно проверить выполнение жестов, сходство, точные русские реплики, губы, тембр и прозрачный WebM. Если GenAPI отклонит новую комбинацию reference inputs, ошибка сохраняется без скрытого перехода на платный Kling.

## SCRUM-62 — Исправление реального HTTP 422 (21.11.2026)

Реальное задание `f6c7939e-87cd-4717-8956-fe2b7aa0e1de` было остановлено GenAPI до видеогенерации:
`GENAPI_HTTP_422 image_url ... video_urls ...`. Прежний код ошибочно посылал `image_url` одновременно с `video_urls`; официальный валидатор запрещает такое сочетание. Тот же JPG остаётся в архиве только для просмотра/скачивания.

- Схема `wanReferenceFields` всегда отправляет одну `video_urls` и не содержит `image_url`.
- При **доказанном именно этом** HTTP 422 (`submitting_model=wan-3`, точный префикс диагностической ошибки, присутствует `video_urls:` и **нет сохранённого `wan-3` request ID**) пользователь может бесплатно проверить сохранённые TTS/Chatterbox GET, затем явно согласиться повторить только новую оплачиваемую видеогенерацию Wan и последующий Lip Sync. Запись и оплаченная речь сохраняются в исходном job.
- PostgreSQL атомарно проверяет владельца, сцену, старые TTS/Chatterbox IDs, статус failed, точный HTTP 422 и отсутствие Wan/LipSync IDs, **только тогда** очищает `submitting_model`. Любой timeout/неизвестный результат POST/имеющийся Wan ID — стоп без оплаты.
- Без согласия пользователя сервер ничего не оплачивает. После исправления frontend показывает тип восстановления и цену будущих видео/LipSync.
- Реальный end-to-end видео результат с клавиатурой и прозрачным фоном ещё требует проверки после первого успешного Wan POST.

Источник схемы: https://gen-api.ru/model/wan-3/api и конкретный ответ GenAPI от пользователя.


## SCRUM-63 — Реальный 402 при видимом остатке 2279 ₽ (21.11.2026)

Owner видит в GenAPI **2279 ₽**, но Wan 3.0 720p, 10 секунд (\`25 ₽/сек = 250 ₽\` по публичному тарифу GenAPI) возвращает \`GENAPI_HTTP_402 На вашем счете недостаточно средств\` до получения \`wan-3\` request ID. Предыдущие оплаченные TTS/Chatterbox ID=58629153/58629167 и исходная камера сохраняются.

Официальная диагностика: \`GET https://api.gen-api.ru/api/v1/user\` по **точно тому же** production \`GENAPI_API_KEY\` (не логировать токен, не отправлять его в браузер), ответ содержит \`balance\` в рублях и \`email\`. Текущий owner-only endpoint \`studio/keyboard-rap/{jobId}/recovery-quote\` автоматически выполняет этот бесплатный запрос именно при 402. Возвращаются \`railwayApiAccount.balanceRubles\`, маска аккаунта и флаг \`coversPublishedWanVideoPrice\`; это позволяет понять, соответствует ли пользовательский кабинет фактическому ключу Railway. При ошибке запроса и при балансе меньше 250 ₽ платная кнопка заблокирована.

**Принцип сохранения денег:** Доказанный \`GENAPI_HTTP_402\` от биллинга с \`submitting_model=wan-3\`, текстом \`недостаточно средств\` и отсутствием платного \`wan-3\` ID — окончательный отказ до создания video task; он отличается от сетевого таймаута и других неоднозначных POST. Один и только один новый Wan POST по ИСХОДНОМУ job может быть разрешён, если:
1. TTS и Chatterbox имеют сохранённые ID и \`success\` при бесплатном GET;
2. тот же ключ production имеет \`balance>=250\` по официальному GET;
3. \`__diag.wan402RetryCount=0\` (или отсутствует), нет \`wan-3\` и \`lipsync\` ID;
4. пользователь отдельно подтверждает платную попытку.
Сервер атомарно обновляет \`submitting_model=NULL\` и сохраняет \`__diag.wan402RetryCount=1\` перед worker. Повторный HTTP 402 заблокирует дальнейшие автоматические и ручные ресабмиты из этого маршрута — сначала нужна сверка провайдерского биллинга. Старые TTS/Chatterbox не оплачиваются повторно.

Величина 250 ₽ — **публичная оценка, НЕ ограничитель расходов провайдера**. Если API показывает 2279 ₽, но продолжает отклонять запросы по 402, это не основание бесконечно пополнять баланс. Зафиксировать противоречие для GenAPI по тому же API-аккаунту. Никакие billable POST не выполнялись при изменении кода или сборках.
